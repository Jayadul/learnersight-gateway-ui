SendText Integration Guide

Single endpoint for dispatching SMS, WhatsApp and Voice messages, with automatic fallback when a delivery fails. Share this page with any third-party application that will integrate.

Endpoint

POST {{ baseUrl }}/sendtext
Content-Typeapplication/x-www-form-urlencoded
Authenticationapikey + secretkey form fields (issued by NetZero). Invalid or missing credentials are rejected
ProcessingAsynchronous. The response confirms queuing, not delivery
GatewaysEach channel type may have several gateways configured. A message goes to that type's default gateway unless its tag names one
PacingA WhatsApp gateway may be given a send delay to stay under provider rate limits, so its deliveries arrive spaced out rather than all at once. A long recipient list takes proportionally longer

Request Parameters (form fields)

FieldRequiredDescription
toUser Required Recipient number(s) with country code, e.g. 8801700000001. For multiple recipients, separate with commas: 8801700000001,8801700000002. Every number receives every tagged message.
messageContent Required The message. Use channel tags (below) to pick channels. Without any tag the whole content is sent as a plain SMS.
apikey Required API key issued by NetZero. Requests with a wrong or missing key are rejected.
secretkey Required Secret key issued by NetZero. Keep it confidential. Use it server-side only, never in client-side code.
callerID Required Sender ID recorded with the request.

Channel Tags

Compose messageContent from one or more [tag::content] blocks. Each tag creates one delivery, and several tags may be combined in a single request. There are three channels — SMS, WhatsApp and Voice — and an unrecognised tag rejects the whole request rather than being skipped.

TagChannelExample
[sms::TEXT] SMS [sms::Your OTP is 123456]
[wp::TEXT] WhatsApp [wp::Hello, your appointment is confirmed.]
[wp::TEXT||URL] WhatsApp with media — the same tag; the URL is what makes it a media message [wp::Please review the invoice.||https://example.com/invoice.pdf]
[sms-wp::TEXT] SMS and WhatsApp (same text, two deliveries) [sms-wp::Big sale this weekend!]
[call::CAMPAIGN_ID] Voice call using the campaign's configured lot [call::due-bill-api]
[call::CAMPAIGN_ID||LOT] Voice call for a specific lot within the campaign [call::due-bill-api||lot-42]
(no tag) Plain SMS with the full content Hello without any tag
Choosing a specific gateway — each channel type may have several gateways configured. Without a label a message goes to that type's default gateway; add a label to name one exactly. Labels are shown against each channel in Settings › Channels.
[sms_label:SLUG::TEXT] SMS through the gateway with this label [sms_label:revemain::Your OTP is 123456]
[wp_label:SLUG::TEXT] WhatsApp through the gateway with this label (media works the same: ||URL) [wp_label:watrendmain::Your appointment is confirmed.]
[call_label:SLUG::CAMPAIGN_ID] Voice call through the gateway with this label [call_label:voicemain::due-bill-api||lot-42]
[sms_label:A-wp_label:B::TEXT] The combined send, with each leg on a named gateway. Either leg may be labelled on its own — the unlabelled one uses its type's default [sms_label:revemain-wp::Big sale this weekend!]

|| means the same thing everywhere: it separates a media URL from its caption, and a lot number from its campaign id.

Automatic Fallback

If a delivery fails at the provider, NetZero can retry it on another channel. Which retries happen is configured by NetZero, not by the request — three rules decide whether one applies:

Same type by default A failed WhatsApp send retries on another WhatsApp channel, SMS on another SMS, Voice on another Voice. Retrying across types changes both the delivery format and the per-message cost, so it has to be enabled deliberately.
One tag only A request that asks for more than one delivery never gets a fallback — for example [sms::…][wp::…] or any [sms-wp::…] form. The second channel is already the redundancy, so no third message is generated and nothing extra is charged.
Visible either way A retry appears in Message Logs as an extra delivery badged Fallback. When a retry is skipped, the message detail says so.
